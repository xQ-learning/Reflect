# Reflect · 目标复盘

围绕「目标—结果差距」的轻量复盘工具。一个目标就是一次复盘：写下要什么、配一条能检验的标准，再把结果、事实、原因和改进攒起来。

原生 Android 应用（APK），数据全部存在本机，离线可用。

---

## 核心模型

主角是**目标**，不是「复盘项目」。一个目标 = 一次复盘。

界面是三个横向页签：

| 页 | 内容 |
|---|---|
| **目标集** | 过往定过的目标的只读索引。点卡片进入**战报回放**（只读），想改点「编辑」 |
| **复盘** | 核心工作台。一个目标的复盘，纵向三个模块 |
| **统计** | 总体信息 + 两个目标之间的对比 |

**战报回放（只读）**：从目标页点开一个目标看到的完整回顾，两个模块：

| 模块 | 内容 |
|---|---|
| 📊 预期 vs 现实 | 目标（🎯 + 状态）→ 💡 预期（验证标准）→ ⚠️ 现实（实际结果 + 指标）→ 🔴 差距（目标差距）。指标不用表格，用**粗体红绿**对照 |
| 🕰️ 经验时间线 | 事实按时间线排（🕒 时间，🔴 问题 / 🟢 好消息），每条下面挂 🔍 原因 和 🛠️ 装备（改进），没有装备的写「暂无经验沉淀」 |

整页没有输入框，也没有任何可点操作，更没有底栏 —— 内容直接铺满到底。
顶栏是「< 返回」（左）/ 【战报回放】（居中）/「编辑 >」（右），两个按钮都是无边框的纯文字。
（导出分享暂时撤下，复盘页顶栏还有。）

**复盘页的三个模块**：顶部是一条**悬浮步骤条**（🎯 1.目标 → 📊 2.结果 → 📝 3.事实 → 🛠️ 4.归因与装备），
点一下就滚到对应的模块。

| 模块 | 内容 |
|---|---|
| 🎯 目标 | 目标描述 + 验证标准（可一条可多条）。填好了自动折叠成摘要，点一下展开改 |
| 📊 结果 | 实际结果 → 目标差距 → 关键指标（指标名/实际值/目标值）。填好了自动折叠成摘要 |
| 📝 事实与归因 | 像聊天记录：**差距汇总**（最新一条结果）压在最上面，下面每条事实是一张大卡片，原因和装备是卡片下面的「回复」 |

一条事实长这样：

```
🕒 11-16 14:30
┌─────────────────────────────────────────┐
│ 🔴 用户在模板入口停留超过 40 秒后退出   │ 🗑️
│ 💬 点击这里补充原因...                   │
│ 🛠️ 点击这里锻造新装备...                 │
└─────────────────────────────────────────┘
```

写完的原因显示成 `🔍 原因：…`，装备显示成 `🔧 装备：…` 并带一个 `[状态: 待验证]` 的小标记（点它切换状态）。
事实卡片右上角有个极淡的 🗑️，点一下才删。写新事实时先选情绪（🔴翻车 / 🟢爽点 / 🟡平平），时间自动记。

**事实是唯一锚点**：原因和改进都写在某条事实下面（一条事实各一条）。
没有事实就没有归因和改进 —— 改进必须从观察里长出来，不能是凭空许的愿。
改进的验证结论可以隔很久再补，甚至在别的目标下闭环。

流程：定目标 → 记结果 → 记事实 → 归因改进 → 提交复盘 → 进目标页归档。

**目标怎么定**：上面写目标描述，下面写验证标准，填好点「创建目标」就完了。
复盘页一进去就是这三个模块，可以从上往下顺着记；目标还没建时直接记结果，系统会先用第①块的内容把目标建出来。
没有版本链、没有修订版本 —— 目标要改就直接改，改完即当前版本。

**验证为什么可以先不填**：总结出来的经验往往不能即时验证，周期长，甚至可能在别的目标下才闭环。
所以改进措施先记下来，验证结论可以隔很久再补录；只有写下验证结论才能标记闭环。
没有闭环的改进，在对比里会被高亮出来。

**状态**：目标页上每个目标有三种状态 —— `已闭环`（改进全部验证）、`已提交`（复盘已提交但还有改进没验证）、
`进行中`（复盘还没提交）。「填完了吗」和「闭环了吗」是两件独立的事。

不做：绩效追责、全量日志平台、复杂项目管理；对象轴/层级轴对比后置。

### 已知坑

- **`store.persist()` 用 try/catch 吞掉了 `ui.render()` 的异常**：前端 JS 一报错，页面就「静默不更新」，控制台也不报错。排查时先手动调 `Reflect.ui.render()` 看是否抛错
- 往 `/mnt/hgfs/app/` 覆盖**已存在**的文件会被安全分类器判为「Irreversible Local Destruction」拦下来 —— 所以每版都写新的带版本号文件名，用户也明确要求不覆盖 `reflect.apk`
- 本机 Firefox 是 snap 包，受 confinement 限制读不到 `/tmp`，测试要在仓库目录或 `~` 下跑
- 本机没有模拟器（无 KVM）也没有真机，APK 从未在设备上跑过；原生壳部分（WebView 承载、导出文件、分享）只做了静态验证

## 视觉：暗金 / 复古卷轴

内容是 RPG 战报，视觉就跟着走 —— 不是「企业级后台」的冷黑灰，而是一套**带情绪倾向的深色主题**。

| 角色 | 色值 | 用在哪 |
|---|---|---|
| 底色 | `#0a1118` 墨蓝（不是纯黑） | 页面底 |
| 卡片 | `#151e26` 深蓝灰 + 极弱渐变 | 卡片、内嵌块 |
| 主文字 | `#e9e1d0` 羊皮纸白（不是纯白） | 正文 |
| 次要文字 | `#a39a86` 暖石灰 | 说明、时间 |
| 点缀 | `#d4af37` 暗金 | 标题、模块名、主按钮、焦点环 |
| 扣血 | `#f05a5e` 猩红 | 差距、未生效改进 |
| 回血 | `#3fcf8e` 翡翠绿 | 好消息、已闭环前的正反馈 |
| 未鉴定 | `#e8a33c` 琥珀 | `[待验证]` 标签（虚线框，像没鉴定的装备） |
| 已装备 | `#5fd4e8` 青蓝 | `[✓ 已闭环]` 标签（带一点发光） |

质感上的三件事：

- **底子有纹理**：页面底色上叠一层极淡的网点，再从顶部洒下一束暖光，不是死板的纯色
- **卡片浮在夜色上**：左上到右下的极弱渐变 + 1px 金色微光描边 + 带色的弥散投影（`--lift`），而不是纯色 div 加圆角
- **按钮是金属的**：主按钮是斜向渐变的金属金，配深墨色字和暖色投影；输入框是「刻进皮革的凹槽」（内阴影 + 更暗的底），聚焦时亮起金边

## 构建

环境要求：Android SDK（build-tools 34 + platform android-34）、JDK 17。**不需要 Gradle、Node、npm 或 pip。**

```bash
./build.sh                 # 产出 build/reflect.apk（已签名）
adb install -r build/reflect.apk
```

构建流水线是手工串起来的：`aapt2` → `javac` → `d8` → `zipalign` → `apksigner`。

签名密钥在首次构建时自动生成到 `keystore/reflect.jks`（已 gitignore）。
**后续版本必须用同一个密钥签名才能覆盖安装**，请把这个文件备份好。

环境变量可覆盖路径：`ANDROID_HOME`、`BUILD_TOOLS_VERSION`。

## 架构

```
┌─ 原生壳 (Java) ─────────────────────────────────┐
│  MainActivity: WebView 承载 assets 前端           │
│  · assets 映射到虚拟域名 https://reflect.local/   │
│    （不用 file:// 是为了让 localStorage 有稳定     │
│     origin，否则数据存不住）                      │
│  · AndroidBridge: saveFile / share / toast        │
│  · 返回键交给前端 Reflect.ui.onBack() 消费        │
  │  页面：目标 / 复盘 / 统计（底部三页签）        │
└───────────────────┬──────────────────────────────┘
                    │ file:///android_asset 内联
┌───────────────────┴──────────────────────────────┐
│  前端 (原生 JS，无框架 / 无构建 / 无 CDN)          │
│  store.js    数据层，localStorage 持久化          │
│  compare.js  中文友好的原因相似度与对比            │
│  export.js   Markdown 报告与摘要                  │
│  ui.js       hash 路由与渲染                      │
└──────────────────────────────────────────────────┘
```

**数据层是唯一的存储出入口**（`Reflect.store`），UI 只调它。
纯本地优先，不带服务端；要加同步时只需在 store 层加一个同步适配器，UI 不用改。

设备间流转通过「导出 Markdown / 导入」。

## 数据模型

localStorage 键 `reflect.v2`：

```
goals[] = {
  id, goal: { description, criteria: [string] },
  results[], facts[], causes[], actions[],
  linkedGoalIds[], createdAt, updatedAt, submittedAt
}
```

- `facts[]`：`{ id, content, timelineAt, mood(bad/good/flat) }` —— `mood` 是记录时选的情绪，老数据没有这个字段时按文本里的正向词推断
- `causes[]`：`{ id, text, factId }` —— 锚到一条事实
- `actions[]`：`{ id, title, factId, verifyResult, status(open/verified/failed), closedAt }`

## 功能

- **目标集**：过往目标的只读索引 —— 每张卡片是 `💥 目标（状态）` / 核心指标（完成率 60% · 导出失败率 12%）/ `🔥 已掉落 N 件装备（待验证）`，没有进度条；**长按目标卡片**弹出删除菜单，菜单里点一下直接删，不再二次确认
- **战报回放**：点目标卡片进入的只读回顾 —— 「📊 预期 vs 现实」+「🕰️ 经验时间线」两个模块；铺满整屏不显示底栏；顶栏「编辑 >」进复盘页修改，「< 返回」回目标页
- **复盘页**：一个目标的复盘（三个模块纵向平铺 + 顶部悬浮步骤条）；填好的模块自动折叠成摘要；事实与归因是聊天式时间线，最新一条结果（差距汇总）压在时间线上面，对着差距归因；页头右侧可「载入示例」和导出，底部可「提交复盘」回到目标页
- **底部导航**：目标 / 复盘 / 统计三页签等宽填满整条底栏
- **统计页**：目标总数 / 进行中 / 已闭环 / 改进闭环率；两个目标对比；导出全部报告
- **对比**：高亮**重复原因**和**上次没闭环的改进**（对比后自动关联，导出报告会带上这段）
- **导出**：单目标 Markdown 报告 + 摘要（可存文件或系统分享），以及全部目标的合集报告

### 核心行为

| 行为 | 实现 |
|---|---|
| 目标必须有验证标准才能创建 | `validateCriteria()` 至少 1 条；不满足时按钮拒绝写入并提示 |
| 修改目标即覆盖 | `updateGoal()` 直接写当前目标，没有历史版本 |
| 改进没有验证结论不能闭环 | `closeAction()` 在 `verifyResult` 为空时返回 `{ok:false}`，UI 拦截并提示 |
| 提交复盘打上标记 | `submitGoal()` 写入 `submittedAt`，目标页据此显示「已提交」 |
| 原因和改进必须挂在事实下面 | 在「📝 事实与归因」模块里按事实内联编辑，模型上 `cause.factId` / `action.factId` |
| 删事实会带走它的原因和改进 | `removeFact()` 级联清理，不留孤儿条目 |
| 对比高亮重复问题 | 中文不能靠空格分词，用**字符 bigram 的 Jaccard + 关键词集合重叠**混合打分，阈值 0.45 |
